## 調査結果

### バージョン対応
- Mindcraft README: Minecraft 1.21.11 まで（推奨 1.21.6）。最新リリース v0.1.4（2026-03）、develop の最終コミット 2026-10-02。
- mineflayer 4.33.0 は 1.21.8 まで。4.39.0 は 1.21.11 と 26.1 まで。**26.3 はどの版でも非対応**。
- Mindcraft は `package-lock.json` を持たないため、そのまま `npm install` すると最新の mineflayer / minecraft-data が入り、4.33.0 向けのパッチが一部外れる。
- 他のパッチ対象（mineflayer-pathfinder 2.4.5 / pvp 1.3.2 / prismarine-viewer 1.33.0 / protodef 1.19.0）は最新版＝パッチ対象版。minecraft-data のパッチ（3.97.0用）は 3.117.0 では本家修正済みで、バージョン不一致の警告が出るだけ。

### Node 24
- 原因は `gl`（headless-gl 8.1.6）。darwin-arm64 用のビルド済みバイナリは Node 18/20/22 用だけで、Node 24 ではソースビルドになり C++20 エラーで失敗する。
- `gl` を使うのは vision 機能（`camera.js` → `node-canvas-webgl`）だけだが、`agent.js` から静的 import されていて vision 無効でも読み込まれていた。
- 対応: `canvas` / `node-canvas-webgl` を optionalDependencies に移し、`vision_interpreter.js` で `camera.js` を動的 `import()`。Node 24 では node-canvas-webgl ごとスキップされるが起動できる（vision は使えない）。

### Claude 連携（対応前の状態）
- `@anthropic-ai/sdk` 0.17.1 と古かった。呼ぶのは `messages.create` だけ。
- 標準モデルは `claude-sonnet-4-6`。`profiles/claude_thinker.json` の `budget_tokens` は新モデルでは 400（Sonnet 4.6 ではまだ動く）。
- プロンプトキャッシュ未対応で、プロンプトの並び（毎回変わる状態がコマンド一覧より前）のせいで `cache_control` を付けるだけでは効かない構造だった。
- 埋め込みは `openai` 指定だが、キーがなければ単語一致方式に自動で切り替わる（起動時の「Error with embedding model, using word-overlap instead.」×3 は想定どおり）。
- 日本語は `settings.language` で Google 翻訳を経由する作り。Claude に直接日本語で話させる方が自然。

### 新モデルAPIの確認結果
- 会話がアシスタント発言で終わると 400（"does not support assistant message prefill"）。Mindcraft では `coder.js` の `!newAction` 分岐で起こりうる → `claude.js` で末尾に `_` のユーザーメッセージを補って対策。
- Haiku 5.5 / Sonnet 5.5 とも `output_config.effort` が使える。Haiku は `thinking: {type: "disabled"}`、Sonnet 5.5 は `thinking: {type: "between_tools"}` が通る。
- 記憶の保存（`promptMemSaving`）や bot への返答判定は、指示を全部 system に入れて会話を空で送る作りなので、ユーザー発言が `_` だけになる。Sonnet 5.5 が「アンダースコアだけ届いた」と反応したことがある（改善候補）。

## 動かしてみて分かったこと

- LAN公開のポートは指定しないと毎回ランダム。公開時に55916を指定すれば settings.js どおりで繋がる。`MINECRAFT_PORT=<番号>` の環境変数でも指定できる。
- `settings.language` を変えなくても、日本語で話しかければ Claude が日本語で返す。
- ワールドを閉じると bot は切断され、再接続に1回失敗すると「exited too quickly」で再起動をやめる。
- 退出・切断の原因は Minecraft 側のログ（`~/Library/Application Support/minecraft/logs/latest.log`）に出る。
- 建築など複雑な作業は `allow_insecure_coding`（AIがコードを書いて実行）が必要。オフだと「家を建てて」と頼んでも材料集めを繰り返すだけ。
- 書いたコードは `bots/<名前>/action-code/<番号>.js` に残る（プロセス再起動で番号が0から振り直され上書きされる）。

## プロンプトキャッシュ

- 仕組み: プロンプト中の `<<<DYNAMIC>>>` より前（キャラ設定＋コマンド一覧、約3,000トークン）を `cache_control` 付きの system に、後ろ（目標・記憶・状態・持ち物・回答例）を最新メッセージの末尾に移す（`src/models/claude.js`）。目印がないプロンプト（記憶の保存など）は従来どおり。
- 実測（Haiku 5.5、20回）: キャッシュ率 75%、費用 61%減、平均応答 1.68秒 → 1.34秒（条件が違うので参考値）。
- 約5往復ごとに履歴が要約されて先頭が削られるため、そのときは会話履歴のキャッシュが外れ system 部分だけがヒットする（想定どおり）。

## ダメージで退出する不具合（解決）

- 症状: ダメージを受けると bot が退出。Minecraft のログに「lost connection: プレイヤーの不正な動きを検知しました」。
- 原因: ステップ1で mineflayer を 4.33.0 に固定したが minecraft-data は 3.117.0 が入り、1.21.6 のプロトコル定義の形が食い違っていた（`entity_velocity` が `velocityX/Y/Z` → `velocity` になるなど約15か所）。ノックバックの速度が NaN → 不正な座標を送信 → キック。
- 対応: mineflayer を 4.39.0 に更新し、パッチを作り直した。use_item の向き・水中の採掘速度は 4.39.0 で本家修正済み。設置待ち時間（5秒→0.5秒）は 4.39.0 で設置処理が作り直された（サーバーの返事ですぐ決着する）ので外した。`incorrect_for_wooden_tool`（鉄鉱石などの採掘時間）だけ残した。
- ついでに直したもの:
  - `connection_handler.js`: NBT 形式の切断理由が `[object Object]` と表示されていた → 中身を表示。`invalid_player_movement` も判定。
  - `modes.js`（本家の不具合）: unstuck 中に別の行動で中断されると強制終了タイマーが止まらず、10秒後に「Got stuck and couldn't get unstuck」で再起動していた → try/finally で必ず止める。
  - `skills.js`: ブロック設置失敗時に理由もログに出す。
- 確認: 埋まった状態で窒息→死亡→リスポーンしても切断なし。ゾンビに殴られても切断なし。

## mochi（Sonnet 5.5）のプレイ記録

### 1回目（75回、約$0.49）
- 良かった点: 性格・口調が設定どおり。危険の注意も自然。「2回失敗したら止まって助けを求める」が効いた。失敗の原因を分析してやり方を変えるのが Haiku より上手。
- 問題: (1) 出力の形が崩れる（約10件）: `<invoke name="placeHere">` などのツール呼び出しの書き方や `<think>`、英語の独り言がチャットに出る。(2) 空っぽの返事（text なし）→ "No response from Claude." がチャットに出て頼みごとが流れた。(3) 夜に装備なしで外に出て5回死亡。
- 対策（ユーザー判断で (1)(2) のみ）: mochi.json に「セリフと平文のコマンドだけ書き、タグ・ツール呼び出しの書き方・考えごとは書かない」を追加。claude.js で text が空なら1回だけ再リクエスト（タブ1文字は有効な返事）。夜の行動の指示はユーザーが不要と判断。

### 2回目（232回、約$1.46）
- **タグ・考えごとの混入 0件、空の返事 0件**（対策が効いた）。tool use への作り替えは当面不要。
- 1回あたり約$0.006、キャッシュ率62%、平均2.9秒 → 遊ぶと1時間あたり約$1.5。
- 死亡2回（クリーパー、溺死）。コード実行中の強制終了 → 自動再起動が1回。
