## ダメージで退出する不具合（2026-10-12 解決）

- 症状: ダメージを受けると bot が退出する。Minecraft 側のログ（`~/Library/Application Support/minecraft/logs/latest.log`）に「haiku lost connection: プレイヤーの不正な動きを検知しました」。
- 原因: ステップ1で mineflayer を 4.33.0 に固定したが、minecraft-data は 3.117.0 が入り、1.21.6 のプロトコル定義の形が食い違っていた（`entity_velocity` が `velocityX/Y/Z` → `velocity` に変わるなど約15か所）。ノックバックの速度が NaN → 不正な座標を送信 → サーバーがキック。
- 対応: mineflayer を 4.39.0 に更新。パッチは `incorrect_for_wooden_tool`（鉄鉱石などの採掘時間）だけ残した。use_item の向き・水中の採掘速度は 4.39.0 で本家修正済み。設置待ち時間（5秒→0.5秒）は 4.39.0 で設置処理が作り直され、サーバーの返事ですぐ決着するようになったので外した。
- 教訓: **mineflayer と minecraft-data は同じ時期の版を組み合わせること**。片方だけ固定すると壊れる。退出の原因はまず Minecraft 側のログを見ると早い。
- ついでに直したもの:
  - `connection_handler.js`: NBT 形式の切断理由が `[object Object]` と表示されていた → 中身を表示。`invalid_player_movement` も判定。
  - `modes.js`（本家の不具合）: unstuck（自動脱出）中に別の行動で中断されると、強制終了タイマーが止まらず10秒後に「Got stuck and couldn't get unstuck」で再起動していた → try/finally で必ず止める。
  - `skills.js`: ブロック設置失敗時に理由もログに出す。
- 確認: 埋まった状態で窒息→死亡→リスポーンしても切断なし。ゾンビに体力1まで殴られても切断なし。作業台の設置成功（戦闘中は失敗することがある）。

## mochi（Sonnet 5.5）初プレイの記録（2026-10-12）

- 75回呼び出しで約$0.49（約20分）。通常の返事は1回約$0.005・平均2.3秒、コード生成は1回約$0.024・約11秒。キャッシュ率62%。→ 遊ぶと1時間あたり約$1.5の見込み（事前の見積もり「1回約$0.002〜0.003」より高かった。夜は周りの敵の情報などで毎回変わる部分が約1,000トークンに増え、思考を含む出力も多い）。
- 良かった点: 性格・口調が設定どおり。危険の注意も自然。家の拡張で2回失敗 → 「2回失敗したら止まって助けを求める」ルールが効いて方向を質問してきた。失敗の原因（天然の砂岩と家のブロックの区別）を分析してやり方を変えるのが Haiku より上手。
- 問題1: **出力の形が崩れる**（10回中に約10件）。`<invoke name="placeHere">` のようなツール呼び出しの書き方や、`<think>` や英語の独り言（"Actually I must output a single command..."）がチャットにそのまま出る。新しいモデルはツール呼び出し用の仕組みに慣れているが、Mindcraft は `!command` を文字で書かせる方式のため。
- 問題2: **空っぽの返事**（出力1トークン、text なし、stop_reason end_turn）→ claude.js が "No response from Claude." をチャットに出し、頼みごとが流れた。
- 問題3: 夜に装備なしで外に出て5回死亡（ゾンビ・蜘蛛・エンダーマン）。リスポーン後に死亡地点へ戻ってまた死ぬ。エンダーマンを怒らせた。
- 対策（2026-10-12 実施、ユーザー判断で (a)(b) のみ。(d) は不要とのこと）:
  - (a) mochi.json の conversing に「返事はすべてチャットに出る。セリフと平文のコマンド1つだけを書き、XMLタグ（<invoke> や <think>）・ツール呼び出しの書き方・考えごとや言い直しは書かない」を追加。※同じ場面を10回ずつ試したが、追加前も後も崩れは0回で再現できず、効果はゲーム内で測る必要がある（崩れは長い会話で起きやすいと思われる）。
  - (b) claude.js: text が無い（空）の返事なら1回だけ再リクエスト。タブ1文字（「言うことなし」）は有効な返事として扱う。2回とも空なら従来どおり "No response from Claude."。モックで動作確認済み。
  - 次に遊んだあと、ログの `<invoke` `<think` `No response from Claude` 等の件数を数えて効果を確認する（今回は75回中約10件）。残るなら (c) の tool use 化を検討。
- 対策案（当初）: (a) プロンプトに「タグ・ツール呼び出しの書き方・考えごとは出さず、セリフと `!command` だけ書く」を追加 (b) claude.js で text が空なら1回だけ再リクエスト (c) 根本対策として Claude のツール呼び出し（tool use）方式に作り替え（大きい） (d) 夜・装備なしのときは外に出ない／死亡地点に急いで戻らない、をプロンプトに追加

## 調査結果

### バージョン対応
- Mindcraft README: Minecraft 1.21.11 まで（推奨 1.21.6）。最新リリース v0.1.4（2026-03）、main の最終コミット 2026-10-02。
- **現在は mineflayer 4.39.0 を使用**（2026-10-12 に 4.33.0 から更新。下の「ダメージで退出する不具合」参照）。
- mineflayer 4.33.0（Mindcraftのパッチ対象）は **1.21.8 まで**。最新 4.39.0 は 1.21.11 と 26.1 まで。**26.3 はどの版でも非対応**。
- Mindcraft は `package-lock.json` を持たないため、そのまま `npm install` すると mineflayer 4.39.0 / minecraft-data 3.117.0 が入り、4.33.0 / 3.97.0 向けの patch-package パッチが外れる。一部は本家で修正済みだが、「ブロック設置後の待ち時間 5秒→0.5秒」パッチは効かなくなる。→ バージョン固定 or パッチ作り直しが必要。
- 他のパッチ対象（mineflayer-pathfinder 2.4.5 / pvp 1.3.2 / prismarine-viewer 1.33.0 / protodef 1.19.0）は最新版＝パッチ対象版なので問題なし。

### Node 24
- 原因は `gl`（headless-gl 8.1.6）。darwin-arm64 用のビルド済みバイナリは node-v108/115/127（Node 18/20/22）だけで、Node 24（v137）用がない。Node 24ではソースビルドになり C++20 エラーで失敗する（FAQ記載）。
- `gl` を使うのは vision 機能（`src/agent/vision/camera.js` → `node-canvas-webgl`）だけ。ただし `agent.js` が `vision_interpreter.js` と `browser_viewer.js` を静的 import しているので、vision 無効でも起動時に読み込まれる。→ `canvas` / `node-canvas-webgl` を optionalDependencies に移し、`vision_interpreter.js` で `camera.js` を動的 `import()` するよう修正済み。Node 24 では `gl` のビルドが失敗して node-canvas-webgl ごとスキップされるが、起動はできる（vision は使えない）。

### Claude 連携（`src/models/claude.js`）
- `@anthropic-ai/sdk` ^0.17.1 と古い。呼んでいるのは `messages.create` だけなので更新は容易なはず。
- 標準モデルは `claude-sonnet-4-6`。`profiles/claude_thinker.json` の `thinking.budget_tokens` は Sonnet 5.5 / Opus 5.5 などの新モデルでは 400 エラー（`output_config.effort` を使う）。
- 新モデルはアシスタント発言で終わる会話（prefill）を送ると 400。`strictFormat()`（`src/utils/text.js`）は先頭が user になるようにはしているが、末尾はチェックしていない → 要検証。
- プロンプトキャッシュ未対応。システムプロンプトが「キャラ設定 → 状態（位置など毎回変わる）→ コマンド一覧（約8,000文字）→ 例」の順なので、`cache_control` を付けるだけでは効かない。固定部分を前、可変部分を後ろ（できればユーザーメッセージ側）に並べ替える必要がある。
- 埋め込みは `openai` 指定だが、キーがなければ単語一致方式に自動で切り替わる（動作には問題なし）。
- 日本語は `settings.language` で Google 翻訳を経由する作り。Claude に直接日本語で話させる方が自然そう。

### 新モデルAPIの確認結果（2026-10-12）
- 会話がアシスタント発言で終わると Haiku 5.5 などで 400（"does not support assistant message prefill"）。Mindcraft では `coder.js` の `!newAction` 分岐（コード生成オン時）で起こりうる → `claude.js` で末尾に `_` のユーザーメッセージを補って対策済み。
- Sonnet 5.5 に `thinking: {type: "enabled", budget_tokens}` を送ると 400。Sonnet 4.6 ではまだ動く（本家の `claude_thinker.json` は4.6なので今は壊れていない）。
- Haiku 5.5 / Sonnet 5.5 とも `output_config.effort`、Haiku は `thinking: {type: "disabled"}`、Sonnet 5.5 は `thinking: {type: "between_tools"}` が通る。短い質問なら応答は1〜2秒。
- 記憶の保存（`promptMemSaving`）や bot への返答判定は、指示を全部 system に入れて会話を空で送る作りなので、ユーザー発言が `_` だけになる。Sonnet 5.5 が「アンダースコアだけ届いた」と反応したことがある → 改善候補。
- 応答ごとに `Received. (xxxms, input: ..., cache read: ..., cache write: ..., output: ...)` がログに出る。ステップ3のキャッシュ効果の測定に使える。
